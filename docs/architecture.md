# 架构与设计取舍

## 从练手代码到应用

原项目 `test/drawing_graph.py` 提供 OCR、视觉提取和工具复核循环。本项目沿用领域问题与证据契约，建立独立 Python 包、应用边界和完整的知识/记忆链路。源练手目录保持原状。

核心路径由 LangGraph 显式编排；视觉 Agent 在其中使用 LangChain 工具调用。工作流的输入、状态、预算和复核节点可直接从源码检查。

## 状态与执行边界

`AgentState` 保存页面、OCR、检索结果、已激活 Skill、项目记忆、模型消息、候选对象和问题列表。messages 使用 add_messages 合并，timeline 追加节点耗时。工具总次数默认 6，推理轮数默认 3，修复次数默认 1；同一条消息中的多个工具请求逐项消耗预算。

`Runner` 为每次调用打开 Qdrant、SQLite saver 和记忆库，退出时关闭资源。run_id 唯一标识任务。已有运行不能以新输入覆盖，resume 必须指向待复核中断。检查点恢复时读取原任务的模式与项目。

## RAG

1. Markdown 标题树建立来源路径。
2. 每个标题段落构成父块；超过 1,800 字符时继续按段落拆分。
3. 子块 420 字符、重叠 80，优先段落、换行、中文句号与分号。
4. 使用内容摘要与来源生成稳定 chunk ID。子块用于向量匹配，父块进入模型上下文。
5. Qdrant 存储向量、heading、parent_id、content_hash 与 embedding_fingerprint。
6. Dense top-12+ 与字符 n-gram 词项排序以 RRF（k=60）融合，按父块去重，默认输出 4 个父块。

词项支路在应用端读取当前知识集合并排序，适合规则手册规模的知识库。大规模语料可将此支路替换为服务端全文索引，保持相同的引用契约和 RRF 接口。

本地 Hash Embedding 为 384 维字符 n-gram 哈希特征；OpenAI 兼容 Embedding 后端用于语义向量。SQLite 缓存以模型指纹与文本摘要为键。指纹包含模型名和端点，索引查询前检查一致性。重建先 upsert，再删除失效 ID；维度变化时切换新 collection。Qdrant Local 使用单进程访问，服务端模式支持共享向量存储。

## Tools 与 Skill

工具闭包由应用注入当前任务页面、项目 ID 和知识/记忆服务。模型提供页 ID 与区域，不提供任意文件路径。OCR 工具在任务页面范围内裁剪，返回的文字坐标统一映射到原图。

Skill 是版本化的领域操作步骤：注册表只发现内置 assets/skills，按 OCR/任务触发词选择，Agent 也可通过 load_skill 加载。Skill 内容和检索规则作为任务上下文进入提示词，系统契约规定其数据地位。

## 双层 Memory

检查点保存当前任务的完整状态。长期记忆表以 (project,key) 为主键，记录约定、来源任务、复核人、更新时间。人工复核通过且修订再次满足证据规则后，独立 memory 节点执行幂等 upsert。

记忆以 convention / review_policy 分类，具体桩号不进入长期约定。下次任务按相同 project 读取；其他项目无法通过工具参数切换记忆范围。

## 证据与复核

Pydantic 约束字段类型和区域；程序校验 OCR 快照、引用存在性、页面归属、桩号原文、名称分组、邻井对象和设备列表一致性。Schema 错误或模型调用异常由运行入口返回错误；业务证据问题进入图内修复。

复核节点使用 interrupt 循环：无效决策产生新的中断，错误信息随下一次请求返回；原始 OCR 始终保留。确认后的规则记忆写入独立节点。拒绝分支结束任务并保留 run.json 状态。

## 模型与数据流

live 模式要求端点支持图像输入、工具调用和所配置的结构化输出方法。每页提供整图及最多六块重叠切片，一次任务最多 12 页。具体 OCR 行保存在不可由模型修改的原始快照中，模型追加区域化视觉观察。工具 OCR 成功结果可增补原始文字来源。

人工与程序校验处理字段、证据和可表达的拓扑约束；图像引线与漏识别的质量通过人工复核和后续真实标注集评估持续迭代。

## 运行模型

CLI 和 API 共用 Runner。HTTP 接口同步返回本次执行结果；待复核任务通过单独端点恢复。API 内有进程内锁串行访问本地 Qdrant；多工作进程部署需 Qdrant Server，并为任务调度配置跨进程锁或队列。同一 run_id 由一个执行者持有。
